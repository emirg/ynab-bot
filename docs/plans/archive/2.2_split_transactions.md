# Plan: Milestone 2.2 - Split Transaction Parsing & Creation

## Objective & Context
- **Status:** Complete
- **Harness Roadmap:** Ignore
- **Goal:** Unify the parsing of shared expenses (intent `shared_expense`) and the creation of subtransactions in YNAB so that a single user message registers the split expense accurately.
- **Why:** To allow users to effortlessly log shared expenses (e.g., "almuerzo a medias 50000 con Juan") which will automatically result in a YNAB transaction composed of multiple subtransactions (e.g., one portion assigned to a "Splitwise" category and the remainder to the "Restaurantes" category).

## Prerequisites (Manual)
- [ ] No infrastructure changes needed. Assumes step 2.1 (`/splitwise` configuration) is already complete and functional.

## Implementation Steps

### [x] Step 1: Update Domain Models
- **Files:** `src/domain/models/expense.py`, `src/domain/models/budget_query.py`
- **Action:** 
  - Update the `Expense` model adding fields: `is_split` (bool), `split_person` (str, optional), and `split_proportion` (str, optional; e.g. "1/2", "0.5").
  - Update `MessageResult` to support `intent == 'shared_expense'`.
- **Tests:** `tests/test_domain_models.py` - Add valid/invalid test cases for split expenses.

### [x] Step 2: Update LLM Expense Parser
- **Files:** `src/parsers/llm_expense_parser.py`
- **Action:** 
  - Enhance `_generate_message_system_prompt()` to instruct the LLM on detecting intent `shared_expense` using words like "compartido", "split", "mitad".
  - Instruct the LLM to output `proportion` and `person` explicitly when this intent is matched.
  - Modify `parse_message()` and JSON validation logic in the parser to return the new fields.
- **Tests:** `tests/test_llm_expense_parser.py` - Test phrases like "almuerzo 50k a medias con Juan" and assert the parser retrieves `intent: shared_expense`.

### [x] Step 3: Integrate Subtransactions in YNAB API
- **Files:** `src/infrastructure/repositories/ynab_api_repository.py`
- **Action:** 
  - Enhance `create_transaction` to support creating YNAB subtransactions if `expense.is_split` is true.
  - The payload must allocate the amounts between the true budget category and the Splitwise category associated with the person in the split group.
- **Tests:** `tests/test_ynab_repository.py` - Mock API requests with subtransactions enabled and check the payload.

### [x] Step 4: Update Expense Service Orchestration
- **Files:** `src/application/services/expense_service.py`
- **Action:** 
  - Update `process_message()` to handle the `shared_expense` intent.
  - Resolve the split category and shared account via `SplitConfigService.get_group_for_alias()` using the person mentioned in the message.
  - Handle logic for "3rd party paid" expenses (e.g., "Juan compró un almuerzo"). If another person paid, it should log into the "Shared Transactions" account and distribute the categories appropriately.
- **Tests:** `tests/test_expense_service.py` - Add test cases where the message is processed as a split transaction, and ensure `create_transaction` is called with correct allocations.

### [x] Step 5: Update Telegram Response Formatter
- **Files:** `src/presentation/telegram/formatters.py`
- **Action:** 
  - Add formatting logic in `ExpenseResponseFormatter` to output the split breakdown (e.g., "Registrado: Almuerzo $50.000 → Splitwise $25.000 + Restaurantes $25.000").
- **Tests:** `tests/test_formatters.py` - Ensure proper Markdown display for splits.

## Constraints & Architecture
- Ensure that the YNAB amounts strictly respect the milliunits convention (`int(amount * -1000)`).
- Subtransactions sum must exactly match the total transaction amount.
- Fail gracefully if the split group or alias isn't configured, suggesting the user to run `/splitwise`.
